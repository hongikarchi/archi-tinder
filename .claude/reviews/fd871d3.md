## Findings (Part A)

### 1. [MINOR] Dead defensive `__action_card__` guards in swipe.py
- **File:** backend/apps/recommendation/views/swipe.py:34, 94, 590, 633, 656, 681
- **Axis:** 5 (Code quality / dead code)
- **Issue:** `engine.build_action_card` is deleted in this branch and no other code path constructs a card with `building_id == '__action_card__'`. The 6 defensive guards in swipe.py (e.g. `if next_card and next_card.get('building_id') != '__action_card__'`) and one in `_merge_buffer_into_exposed` (line 34) are now unreachable defense. The matching frontend helper `isActionCard()` (App.jsx:42) is similarly dead defense (action cards no longer arrive from the backend).
- **Why it matters:** Indicates uncertainty about whether the action-card concept is fully retired. Future readers will wonder if a path still produces these cards. Slight maintenance friction; no runtime cost.
- **Suggested fix:** Remove the 6 guards in a follow-up cleanup commit; optionally also retire `isActionCard()` and the `card_type === 'action'` branch in `frontend/src/api/images.js:62-67`. Defer to a separate cleanup PR — out of scope for S3 if the team prefers conservative rollback safety.

### 2. [MINOR] Frontend `handleExtendSession` ignores `is_analysis_completed=true`
- **File:** frontend/src/App.jsx:466-500
- **Axis:** 2 (Correctness — edge case)
- **Issue:** `handleExtendSession` unconditionally sets `setIsSessionCompleted(false)` and `setCurrentCard(result.next_image)`. If the backend's extend response returns `next_image=null` with `is_analysis_completed=true` (genuine pool exhaustion AFTER `refresh_pool_if_low` cannot find more candidates — see swipe.py:396 `'is_analysis_completed': next_card is None`), the frontend renders the "No more buildings available" empty state (SwipePage.jsx:506-519) instead of staying on the end-screen with the persona-report button.
- **Why it matters:** Mid-experience UX glitch when pool genuinely runs out after the user clicks "Keep exploring." User loses the persona-report CTA and sees a dead-end.
- **Suggested fix:** Mirror `applySessionResponse` logic in `handleExtendSession`: when `result.is_analysis_completed || !result.next_image`, set `setIsSessionCompleted(true)` rather than false, and clear the prefetch slots. Out of scope to gate this PR — the most common path (pool has cards) works correctly.

### 3. [MINOR] No `session_extend` SessionEvent emitted
- **File:** backend/apps/recommendation/views/swipe.py:339-399
- **Axis:** 4/5 (Observability / spec alignment)
- **Issue:** The extend short-circuit increments `session.extended_rounds` and resets `phase` to `analyzing`, but does NOT emit a SessionEvent of type `'session_extend'`. The model's `EVENT_TYPE_CHOICES` (models.py:132) already includes `('session_extend', 'Session Extend')`, implying the schema designer anticipated this event would fire.
- **Why it matters:** Loss of telemetry. Cannot answer "how many sessions hit the 5-cap?" / "what fraction of converged sessions click Keep Exploring?" from current data. Investigation 22 + future end-flow analytics will need this signal.
- **Suggested fix:** After the `session.save(...)` at swipe.py:381-384, call `event_log.emit_event('session_extend', session=session, user=profile, extended_rounds=session.extended_rounds, phase_before='converged', cap_reached=(session.extended_rounds >= 5))`. Also fire from the cap-reached noop branch (line 350) with `cap_reached=True` so admin can distinguish "user tried, got blocked" from "user used a round."

### 4. [MINOR] `SwipeView.post` length / extend short-circuit could extract to helper
- **File:** backend/apps/recommendation/views/swipe.py:303-399
- **Axis:** 5 (Code quality)
- **Issue:** `SwipeView.post` is now ~500 lines (including extend short-circuit, idempotency check, normal swipe processing, prefetch, telemetry). The extend block at 339-399 is self-contained — pulling it into `_handle_extend(session, profile, client_buffer_ids)` would clarify the two distinct request flavors (real swipe vs extend session) and reduce visual coupling.
- **Why it matters:** Cognitive load when modifying the swipe hot path. Refactoring later is harder once more code accretes around the short-circuit.
- **Suggested fix:** Extract `_handle_extend()` helper in a separate cleanup PR. Not blocking — code is correctly delimited and adequately commented.

### 5. [MINOR] Missing test: `extend=true` with empty `building_id`
- **File:** backend/tests/test_sessions.py (TestExtendSessionFlow)
- **Axis:** 6 (Test coverage)
- **Issue:** Commit fd871d3 specifically tolerates empty `building_id` when `extend=true` (swipe.py:332-333: `if not extend_requested and not building_id`). No test exercises that path — `test_extend_flag_serves_next_card` sends `building_id='B00002'` (non-empty). If a future refactor reverts the guard, this regression won't be caught.
- **Why it matters:** Test gap on a fix-commit's exact behavior. The frontend `handleExtendSession` (App.jsx:476) sends `image_id: (project.swipedIds || []).slice(-1)[0] || ''` which can be the empty string for a fresh session; production path depends on this tolerance.
- **Suggested fix:** Add a 6th test to `TestExtendSessionFlow`: send `{'extend': True, 'building_id': '', 'action': 'like'}` and assert 200 + `next_image is not None` + `extended_rounds == 1`.

### 6. [MINOR] Missing test: `extend=true` on non-converged phase (noop branch)
- **File:** backend/tests/test_sessions.py (TestExtendSessionFlow)
- **Axis:** 6 (Test coverage)
- **Issue:** swipe.py:344 covers the noop branch `if session.phase not in ('converged', 'completed') or session.extended_rounds >= 5`. Only the cap-reached half (`extended_rounds >= 5`) has a test (`test_extend_cap_5_returns_completion`). The phase-not-converged half is untested — if someone changes the cap check to `and` instead of `or`, the regression slips through.
- **Why it matters:** Test gap on a defensive guard. The guard exists to prevent extend from being accepted while a real swipe session is still active (which would mutate `extended_rounds` mid-game).
- **Suggested fix:** Add a 7th test: create a session with `phase='analyzing'`, POST `extend=true`, assert response has `accepted=True` but `extended_rounds == 0` (unchanged) and `can_continue=False`.

## Architecture Alignment
Aligns with the Spec v1.6 §11.1 extend-session policy (5-round cap, phase=analyzing reset, `convergence_history=[]` and `previous_pref_vector=[]` reset). The API design — explicit `extend:true` body flag rather than overloading the `building_id` payload — is a clean separation of concerns. The new `AnalysisSession.extended_rounds` column (migration 0017) is a straightforward additive change with `default=0` (backfill-safe for existing rows). The deletion of `engine.build_action_card` is consistent with the new UI flow rendering the end-screen from `isSessionCompleted` state instead of from a card-shaped payload.

Frontend SwipePage end-screen (SwipePage.jsx:399-504) and App.jsx `handleExtendSession` (App.jsx:466-500) sit cleanly inside the existing inline-style design system per `DESIGN.md`.

## Optimization Opportunities
- The extend path calls `engine.refresh_pool_if_low(session, threshold=5)` then `engine.compute_mmr_next(...)` sync (swipe.py:370-376). This adds ~50-150 ms latency to the "Keep exploring" click. Acceptable for an explicit user action; not a perf concern.
- `_progress` helper (`_shared.py:42`) computes `pool_remaining` with a list-comprehension `in` check — O(N*M). Pre-existing across the codebase; out of scope for S3.

## Security Analysis
- Auth flow unchanged. Session ownership intact via `AnalysisSession.objects.filter(session_id=..., user=profile)`.
- `extend_requested = bool(request.data.get('extend', False))` coerces to bool — no injection vector.
- `client_buffer_ids` validated as list of strings ≤ 20 chars, max 10 entries (swipe.py:325-328). ✓
- New `extended_rounds` column has no user-facing input — only server-side increments under `select_for_update` lock. Hard cap of 5 enforced server-side. No bypass possible from client-tampered request bodies.
- The fd871d3 empty-`building_id` tolerance is gated behind `extend_requested` — non-extend swipes still require `building_id` (swipe.py:332). No regression in input validation for normal swipes.
- No new DB writes touch raw SQL; ORM path. No new external API calls in the extend path.
