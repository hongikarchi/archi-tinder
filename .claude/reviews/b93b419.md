### `b93b419` fix: dispatch.sh ESC-force pattern (replaces wrong ✳ filter)
The retrospective fix the cycle-2 dogfood produced:
- **Empirical disproof of the ✳ hypothesis**: same `✳ DEEP REVIEW`
  surface accepted a send in PR #6 cycle and refused it on this
  branch's first dispatch. Surface name does not predict send success
  — Claude Code's current view state does (terminal prompt vs special
  view). The author identified this from logs / direct observation.
- **New approach**: send `Escape` key twice (with `sleep 0.3` between
  each) before any `cmux send`. Esc on a terminal is a no-op; Esc on a
  picker / dropdown / thinking display returns to the prompt. Two
  presses handle the "close picker, then discard partial input" cases.
  `2>/dev/null || true` makes the Esc safe even if the surface
  transiently can't accept it.
- **Empty-string probe removed**: `cmux send "" ` returns "send requires
  text" and exits non-zero unconditionally — was an always-fail probe,
  never useful diagnostically.
- **Net diff**: `+18 / -35` on `dispatch.sh`. Code is shorter, clearer,
  and now matches its own commit-message description (the very issue I
  was about to flag at the prior `0060ce7` cycle is now resolved by the
  diff itself).
- **Empirical validation at HEAD**: my own `.smoke.sh` run during this
  review went through cleanly (4/4 ✓ GREEN), and the user's
  "리뷰해줘" dispatch successfully reached me — so the dispatch path
  works end-to-end at `b93b419`.

## Optimization Opportunities

(All non-blocking; for follow-up backlog if anyone cares)

- `dispatch.sh` adds ~0.6s of `sleep` per dispatch (two `sleep 0.3`s
  between the two Esc presses). Empirical justification ("some Claude
  Code views need 2 Esc presses") is sound. Could be tightened to one
  Esc + 0.3s wait + check-and-retry if cmux exposes a way to read pane
  state; not worth the effort right now.
- `dispatch.sh` review-team auto-`/clear` (lines 90–95) blocks 3 seconds
  unconditionally on every review dispatch. The opt-out
  (`DISPATCH_NO_CLEAR=1`) covers the in-progress-review case. Trade-off
  matches `/review`'s own stateless design (re-reads files each
  invocation) — context-loss cost is genuinely zero.
- `tools/.smoke.sh` runs 2 `git fetch origin develop` calls back-to-back
  (one in `git-new-feature.sh --check`, one in `git-push-pr.sh --check`).
  Idempotent, but could be deduplicated with a short-circuit env var.
  Sub-cosmetic.

## Security Analysis

No new auth surface. No external commands against secrets. New code paths:

- **`dispatch.sh` Esc-Esc + auto-/clear**: `send-key "Escape"` and
  `send "/clear"` are emitted to a cmux pane the operator owns. No
  cross-workspace privilege escalation; no shell expansion of MESSAGE
  before the `send` call (variable is quoted "$flat_msg"). Same trust
  boundary as before this commit.
- **`tools/.smoke.sh`**: pure local subprocess invocations
  (`./tools/git-*.sh --check`). No network outside the existing
  `git fetch origin develop` calls inside the wrapped scripts.
  No env capture, no eval. `set -u` only (intentional — see Architecture
  Alignment).
- **Per-script `--check` modes**: short-circuit early-exit. None of them
  mutate working tree, ref tips, or remote state. `git fetch` updates
  local remote-tracking refs only (no upstream effect). `gh auth status`
  reads gh's credential store (read-only). Safe.
- **`SESSION_PROTOCOL.md`**: pure documentation. No executable content.

`bash -n` clean across all 6 changed scripts (`dispatch.sh`,
