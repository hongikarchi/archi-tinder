## Security Analysis

No auth / token / network / external-dependency code touched. Review focuses on the new shell scripts' input-handling surface:

- **`tools/dispatch-codex-task.sh`** validates `team ∈ {back, front}` via strict allowlist (case match), refuses on bad input with exit code 2. File-existence + readability are checked (exit 3 / 4). The task-file content is read via `sed 's/[[:space:]]\+$//' "$task_file"` (trailing-whitespace strip only) into `$task_body`, then interpolated into a heredoc message via `cat <<EOF ... EOF`. Bash heredoc with **unquoted** EOF expands `$VAR` / `$(...)` / backticks in the **heredoc body**, but does **not** recursively expand those constructs that appear inside the **value** of a substituted variable — so even if `$task_body` literally contained `$(rm -rf /)`, it would be passed downstream as literal text, not executed. Verified safe.
- The wrapped message is then handed to `tools/dispatch.sh "$team" "$message"` as a single positional argument. `dispatch.sh` is out-of-scope for this commit (not in the changed-files list), and the dispatch surface to `cmux send` is unchanged.
- **`tools/cmux_lean_setup.sh`** runs only local `cmux` / `git` / `awk` / `sed` commands against the user's own filesystem. Init prompts are sent via `cmux send` to local workspaces (no network egress). The script's `set -euo pipefail` catches missing-arg / typo failure modes early. No secrets handled; no `eval`.
- **`tools/print-claude-codex-handoff.sh`** is read-only on `git status` / `git branch` output; emits a paste-ready handoff prompt to stdout. No execution surface.
