## Observations (sub-MINOR, not flagged as findings)

1. **Trivial-commit rule LOC ceiling vs docs-only carveout — accidental tension exposed by this very commit.** The existing `Token-saving Rule 2` in CLAUDE.md (and orchestrator.md) defines trivial as **ALL** of: (a) `<50 LOC changed`, (b) no migration, (c) no production code, (d) no auth/network/model layer change. This commit is +119/-2 LOC across 4 files (all under `.claude/agents/*.md`, AGENTS.md, CLAUDE.md), so it satisfies (b)/(c)/(d) but **fails (a)** by 71 LOC. The commit body says "this commit itself is docs/policy (trivial), shipping under the existing 'Skip reviewer + security on trivial commits' rule" — interpreting the rule as spirit-over-letter for pure-docs commits. That interpretation is reasonable, but the rule's literal definition rejects it. Two paths to resolve: (a) tighten the rule to `<50 LOC OR pure docs/policy` (recommended; matches the spirit), (b) accept that >50-LOC docs commits should still go through reviewer/security. This commit landed on path (a) implicitly without updating the rule's definition. Cosmetic; the next time a similar policy doc lands (>50 LOC docs), the same ambiguity will recur.

2. **Hybrid policy lives in CLAUDE.md + team agent files but not in `orchestrator.md`.** Orchestrator.md's Rules section currently says "skip reviewer + security on trivial commits" (Rule 2) but doesn't mention the new hybrid policy ("trust Codex self-review as default; risky-commit override via `(claude-review-requested)` marker"). CLAUDE.md is auto-loaded into every session so the rule is in scope when the orchestrator runs, but if a future orchestrator agent is forked that reads orchestrator.md without re-reading CLAUDE.md, it would miss the hybrid behavior. Sub-MINOR doc-rigor improvement: orchestrator.md should add a 3rd rule explicitly citing the hybrid policy + risky-commit override. Cosmetic; current behavior works.

3. **Risky-commit zone thresholds are empirical not derived.** "Cross-cutting refactor touching ≥4 unrelated apps" (backend) and "≥3 pages" (frontend cross-cutting hook) are empirical thresholds chosen during this docs commit. They could turn out to be too lax (5-app refactor still ships without Claude review) or too tight (3-app refactor unnecessarily triggers review). No way to validate ex ante; first risky-commit dispatch through this policy will calibrate. Cosmetic; the policy explicitly defers to operator judgment via `(claude-review-requested)` opt-in.
