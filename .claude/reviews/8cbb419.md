## Security Analysis

No new code paths cross trust boundaries. The fixes touch:

- **`git-poll-merge.sh`**: exit-code branch logic only. The `gh pr checks
  --json link` extraction (untouched in cycle1) still feeds GitHub-trusted
  data into a stdout handoff signal — no shell interpolation risk.
- **`git-stage-and-commit.sh`**: the `while IFS= read -r leaked; do git
  reset HEAD -- "$leaked"; done` pattern correctly quotes `"$leaked"` so
  filenames with shell metacharacters (`;`, backticks, `$()`) are handled
  literally. Improvement vs the prior unquoted `xargs` form.
- **`git-publisher.md` Mode 1/2 cleanup**: `gh pr view --json state --jq
  .state` returns one of {OPEN, CLOSED, MERGED, DRAFT} — finite, trusted.
  Comparing with `[ ... = "MERGED" ]` is bytewise; no injection surface.
- **`PR_REF=$(gh pr view <N> --json headRefName --jq .headRefName)` then
  `git branch -D "$PR_REF"`**: `headRefName` is the PR's source branch
  name. GitHub allows `/`, `-`, `_`, `.`, alphanumerics in ref names. The
  prior pre-flight assumption was `feature/<role>-<topic>` — but external
  PRs (Mode 2) can carry any author-supplied branch name. Quoting `"$PR_REF"`
  is correct (no word-split). However, `git branch -D` accepts any string;
  if a malicious external PR named its branch `--all` or something with `;`
  in it (GitHub blocks `--` and `;` in ref names anyway), it would still be
  quoted-safe. Confirmed safe.

`git-publisher.md`'s six hard guardrails (never commit source / never push
main / never force-push / never approve own PR / never merge red CI / never
modify CODEOWNERS) are preserved unchanged.
