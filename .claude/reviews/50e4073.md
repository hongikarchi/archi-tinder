## Findings (Part A)

### 1. [MINOR] Redundant null-filter survives the batch refactor
- **File:** `backend/apps/recommendation/views/sessions.py:363`
- **Axis:** 5. Code quality
- **Issue:** Post-refactor `liked_cards = [c for c in liked_cards if c]` is unreachable defensive code. `engine.get_buildings_by_ids` (engine.py:558) returns `[card_map[bid] for bid in canonical_bld_ids if bid in card_map]` — only successfully-fetched cards are present; no `None` entries can survive into the comprehension.
- **Why it matters:** Stale defensive code drifts into noise over time and obscures the actual contract of the batch helper. Reader has to mentally re-verify whether `None` can leak.
- **Suggested fix:** Drop line 363 (`liked_cards = [c for c in liked_cards if c]`) in a follow-up commit; or keep + add a one-line comment `# defensive — get_buildings_by_ids already drops missing IDs`.

### 2. [MINOR] Cold-start exclude-set fix lacks a test that exercises the filter
- **File:** `backend/apps/recommendation/tests/test_discovery.py:22-32` (`test_cold_start_returns_random`)
- **Axis:** 6. Test coverage
- **Issue:** The renamed filter at `views/discovery.py:72,141` now correctly excludes blocked IDs in the cold-start path, but `test_cold_start_returns_random` creates no `Project` rows, so `exclude_set` is empty and the filter is still effectively a no-op under test. A regression to the old `card.get('building_id')` key would still pass this test.
- **Why it matters:** The very class of bug this PR fixes is not covered. A future refactor could silently re-break the filter without a test signal.
- **Suggested fix:** Extend `test_cold_start_returns_random` (or add `test_cold_start_excludes_blocked_ids`) to create a `Project` with `disliked_ids = ['B001']` + `saved_ids = [{'id': 'B002', ...}]`, mock `get_diverse_random` to return cards including `B001` and `B002`, then assert they are absent from the response. Same shape exists for `BoardSurpriseView` cold-start (line 141).

### 3. [MINOR] `getCallHistory()` export has no consumer
- **File:** `frontend/src/api/core.js:22`
- **Axis:** 5. Code quality (dead surface) / 7. Cross-commit drift
- **Issue:** New export `getCallHistory()` returns a shallow copy of the 8-slot ring buffer. Grep across `frontend/src/` confirms zero callers. `DebugOverlay.jsx` still consumes only `getLastCall()`. `api/client.js:10` re-exports `getLastCall` but not `getCallHistory`.
- **Why it matters:** Dead exports calcify into the public API surface. If the planned consumer (concurrent-request latency diagnosis, per commit body) is deferred indefinitely, the ring buffer + export is dead weight rather than instrumentation.
- **Suggested fix:** Acceptable in this commit as scaffolding for the next P-step. If the consumer doesn't land within the perf-ux-overhaul window, either (a) re-export through `api/client.js` to formalize the surface, or (b) inline the ring buffer back to a single slot until the consumer is ready.

## Security Analysis

- **Auth posture unchanged.** `SessionResultView` keeps `[IsAuthenticated]`; `DiscoveryFeedView` + `BoardSurpriseView` keep `[IsAuthenticated]` + their explicit `profile is None → 401` recheck (discovery.py:29, 113).
- **IDOR posture unchanged.** `liked_ids` is derived from `session.swipes.filter(...)` scoped to the matched `AnalysisSession` which is itself scoped to `session_id=session_id, user=profile`. Cross-user surface not introduced.
- **Information disclosure posture IMPROVED.** The cold-start filter fix closes a quiet leak: pre-fix, users with disliked/saved buildings in the exclude_set could still receive those buildings in their first cold-start Discovery feed page or first Surprise modal because `card.get('building_id') not in exclude_set` evaluated `None not in exclude_set` → always True. Post-fix, the exclude_set is honored. Severity of pre-existing leak was low (cold-start is rare; UX bug more than security bug) but the fix is unambiguously the right direction.
- **No new input validation surface.** All edited endpoints retain their pre-existing param parsing (cursor/limit ints, session_id path param).
- **No raw SQL changes in the diff.** `engine.get_buildings_by_ids` is pre-existing and was reviewed at S2 (PR #34); its `IN (placeholders)` uses `cur.execute(..., miss_ids)` parameter binding — not string interpolation — so no SQL injection vector from this branch.
- **Frontend ring buffer holds no secrets.** Stored entries are `{method, url: path, status, ms}`. No tokens, no user IDs. Same exposure as the prior single-slot `_lastCall`.
