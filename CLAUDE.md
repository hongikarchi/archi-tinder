## Operating model — one orchestrator session + Workflow tool

- The session (top session-model tier, Fable 5 as of 2026-08) owns architecture,
  schema, auth, product + release decisions and review. **It does not write
  production feature code.** Every `backend/` or `frontend/` feature, bug fix or
  refactor is delegated: features / unclear bugs / cross-cutting refactors → the
  `orchestrate` skill (launches the `feature` Workflow); bounded mechanical
  changes → `back-maker` / `front-maker` sub-agents (`model: sonnet`). Direct
  edits are allowed only for meta / infra (`tools/`, `hooks/`, `.github/`,
  `.claude/`), single-line policy fixes, sub-MINOR follow-ups and pure docs.
- **ultracode = the Workflow tool.** Build + review runs as a deterministic script
  (`.claude/workflows/feature.js`: back/front-maker → code-review +
  security-manager → Opus adversarial-verify → 2-cycle fix loop). It returns
  `commitReady` and performs **no git**; the publish gate stays in the session.
  `.claude/workflows/review.js` = heavy read-only review of a diff.
- **Model tiers**: session = orchestrator; `opus` + `effort: 'high'` = verify /
  judge; `sonnet` = makers, reviewers, app-test; `haiku` = exploration. Pin `model`
  on every workflow `agent()` call (default inherits the session tier).
- Trivial edits (< 50 LOC, no migration, no production code, no auth/network/
  model-layer change, or pure docs) stay solo: straight to `git-commit`.

Full pipeline, session model, tier table, token rules, known issues: `.claude/WORKFLOW.md`.

## Skills, agents, workflows (roster lives in `.claude/WORKFLOW.md` §2)

- Skills the session runs itself (`.claude/skills/`, also invocable as `/<name>`):
  `orchestrate`, `git-commit`, `git-publish`, `reporter-inline`.
- Sub-agents (`.claude/agents/`, all `model: sonnet`): `back-maker`, `front-maker`,
  `code-review`, `security-manager`, `app-test` (pre-push browser + drift gate),
  `git-publisher` (deploy PR / external-PR triage / rebase recovery only).
- Rule of thumb: isolated work returning a result → agent; a procedure the session
  runs itself → skill; deterministic multi-agent fan-out → workflow.

## Git operations

- Commit → `git-commit` skill. Publish feature → develop → `git-publish` skill
  (push, PR, admin squash, cleanup). Both honor the publish gate in `AGENTS.md`
  § Working and publishing (the only keyword list).
- Escalate to the `git-publisher` agent only for: `develop → main` deploy (needs a
  deploy keyword; runbook `docs/runbooks/deploy.md`), a PR from an external
  collaborator, rebase conflicts needing multi-step recovery, push rejection with
  unclear cause, mid-merge failure.
- Audit before publish: the `reporter-inline` skill records the shipped work in
  the same PR. If it fails, fix `Task.md` / `project/state.js` directly
  (`state.js` is generated by `tools/gen-state.js`; never hand-edit).
- Harness enforcement: `.claude/hooks/git-guard.py` (`PreToolUse(Bash)`, wired in
  `.claude/settings.json`) blocks direct/force pushes to `develop`/`main`,
  `--no-verify`, and `gh pr create --base main` except `--head develop`.

## Pre-push gate — `app-test`

Dispatched by the session after the commit, outside the workflow. FULL mode
(3-persona swipe journey + latency budgets) for recommendation/swipe-path changes;
FEATURE-SCOPED (preflight + caller checklist + light smoke) otherwise; both end
with an `origin/develop` drift check; verdict PASS / PASS-WITH-MINORS / FAIL /
ABORTED. Skipped for pure docs/config, and when pytest + lint/build + code-review +
security all passed on a non-swipe change. Spec: `.claude/agents/app-test.md`.

## Plan mode protocol (durable)

1. Read-only data gathering (Explore agents or direct reads).
2. **Short Korean summary in chat** (5–15 lines). Never dump long English plans.
3. Wait for the user's review before introducing decisions.
4. Decisions **one at a time**, `AskUserQuestion`, 3–4 options with trade-offs,
   Korean labels. Text written before an `AskUserQuestion` is hidden — put the
   substance in a plain message first.
5. Finalize the plan file (Korean summary block + English identifiers), then
   `ExitPlanMode`. Never ask "shall I proceed?" in text.

## Session habits

- Start: `git status` + current branch; if `main`/`develop`, branch first. Check
  that no other session is active in this checkout before any branch operation.
  Scan `Task.md` for `SESSION-START-TODO`.
- Chat replies in Korean; reasoning, docs, commits, PRs in English.
- After a commit the default is STOP; publish only on the trigger words in `AGENTS.md`.
