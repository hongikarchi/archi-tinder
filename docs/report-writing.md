# 결과 리포트 작성 규칙 (BACK-LLM-5)

취향 리포트 텍스트가 **스와이프 데이터로 추적 가능한 사실**에 근거하고, 표현만 자연스럽게 다듬어지도록 하는 규칙.
결정 경위: grilling 세션 2026-09-25~26 (Task.md `BACK-LLM-5`).

## 어디서 고치나

| 무엇 | 파일 |
|---|---|
| 문장 구조 · 문체 · 예시 · 금지 표현 | `backend/apps/recommendation/services/_report_prompts.py` |
| 사실 채택 기준값 (최소 장수, 배수, 비율 등) | `backend/config/settings.py` → `RECOMMENDATION['report_*']` |
| 사실 계산 로직 | `backend/apps/recommendation/services/taste_facts.py` |
| 이 설명 | `docs/report-writing.md` (이 파일) |

## 리포트 구성

| 필드 | 내용 | 언어 |
|---|---|---|
| `persona_type` | 1~2단어 건축 경향 이름 (예: 미니멀리스트). 추상 표현 금지. 보드 이름 기본값으로도 쓰임 | 사용자 언어 |
| `one_liner` | 실제 태그(재료·스타일)가 들어간 구체적인 한 문장 | 사용자 언어 |
| `pattern_paragraph` | ① 스와이프 패턴 사실 문단 | 사용자 언어 |
| `description` | ② 취향 해석 문단 | 사용자 언어 |
| `dominant_programs` / `styles` / `materials` | 태그 칩 + 이미지 생성 프롬프트 입력 | **항상 영어** |
| `taste_facts` | ①의 근거 사실 목록 (화면 비표시, 추적용) | — |

사용자 언어 = `UserProfile.language` (기본 `ko`).

## ① 패턴 문단 (`pattern_paragraph`)

- "보여드린 건물 중…"으로 시작(좋아요·싫어요 사실 모두 동일), 끊기지 않고 이어지는 **한 문단**, 약 200자. 이 도입구는 문단 첫머리에 한 번만 쓰고 사실마다 반복하지 않음.
- `taste_facts`에 있는 사실만 사용. 좋아한 특징 → 넘긴 특징 순서. 숫자는 최대 2개.
- 사실이 하나도 없으면 문단 생략(빈 문자열).

예시:
> 보여드린 건물 중 목재를 쓴 건물은 다른 건물보다 약 2배 자주 고르셨고, 물을 활용한 건물도 약 1.5배 자주 고르셨어요. 반면 유리 커튼월 오피스는 대부분 넘기셨어요.

- 사실별 문장은 아래 틀을 **그대로** 따름. 허용되는 변경은 사실들을 한 문단으로 잇기 위한 어미 연결("고르셨어요" → "고르셨고", 싫어요 앞 "반면")뿐. 싫어요 강도 단어는 "대부분"/"여러 번"만 사용("자주" 등 대체 금지).
- LLM이 가끔 이 규칙과 다르게 쓸 수 있음. 이를 막는 검사·재생성 장치는 두지 않고 받아들임 (2026-09-26 결정).

### 사실 계산

- **보여준 카드** = 프로젝트의 좋아요 목록 ∪ 싫어요 목록 (양쪽에 있으면 좋아요로 셈).
- 비교 대상은 **보여준 카드 안에서 그 특징이 없는 카드**. DB 전체나 다른 사용자와 비교하지 않음.
- **편중도** = (특징 있는 카드를 고른 비율) ÷ (특징 없는 카드를 고른 비율). 작은 표본의 우연을 줄이기 위해 양쪽에 가상 카드 1장씩(고른 것 1, 넘긴 것 1)을 더해 계산.
- 대상 속성: style, atmosphere, color_tone, program, typology_primary, material_visual, typology_tags, architectural_elements, architect_names, 연대(project_year 10년 단위), location_country. 값은 소문자로 통일.

| 사실 | 조건 | 문장 |
|---|---|---|
| 좋아요 | 그 특징 카드 3장 이상 노출, 2장 이상 선택, 편중도 1.5배 이상 | "보여드린 건물 중 ○○ 건물은 다른 건물보다 약 N배 자주 고르셨어요" (특징 없는 카드를 하나도 안 골랐으면 배수 대신 "다른 건물은 거의 고르지 않으셨어요") |
| 싫어요 | 3장 이상 노출, 40% 이상 넘김, **그리고** 선택 편중도가 1/1.5 이하 | 넘긴 비율 80% 이상 "대부분", 40% 이상 "여러 번" 넘기셨어요 — 행동만 서술, "싫어하세요" 금지 |

- 배수 표기: 0.5 단위 **내림** (1.7 → 약 1.5배, 2.3 → 약 2배). 과장 방지.
- 고르는 순서: 편중도 큰 순 → 차이 0.3배 이내면 근거 건물 수 많은 순 → 같은 속성 종류는 1개만 → 근거 건물이 80% 이상 겹치는 사실은 1개만 → 좋아요 최대 3개, 싫어요 최대 1개.

## ② 취향 문단 (`description`)

- 좋아요한 건물의 태그 빈도 + 대표 건물 설명문(`visual_description`)을 바탕으로 해석, 약 300자, 한 문단.
- 해석 허용(예: "빛과 그림자가 만드는 차분한 분위기에 끌리는 편이에요"), 단 새로운 사실은 만들지 않음.
- 부드러운 추정 톤("~한 편이에요"). 좋아요가 적어도 그대로 작성.

## 공통 문체 · 용어

- 해요체.
- 건축 용어는 한글 음차(캔틸레버, 브루탈리즘), 국가명은 한국어(일본, 덴마크), **건축가 이름은 영어 원어**.

## 금지

- 계산하지 않은 비교: "다른 사용자보다", "평균적인 사람보다" 등.
- 최상급 표현: "가장 세련된 취향".
- 성격·인생 판단: "당신은 내향적인 사람이에요".
- 건축가·건물 비하 (특히 넘긴 특징 서술 시).

## 기존 리포트

- 이미 저장된 리포트는 그대로 유지. '다시 생성' 시에만 새 방식으로 작성.
- 공개 보드에서도 동일한 문장을 보여줌.
