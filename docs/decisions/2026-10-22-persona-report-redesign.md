# 페르소나 리포트 UI 개편 설계

**작성** 2026-10-22 · **브랜치** `feature/claude-persona-report-redesign` · **상태** 설계 확정 · 구현 대기 (FULL-REPORT-UI-1)

시연 페이지(`C:\Users\yello\archi-tinder-mock\persona-report-all.html`, 저장소 밖)에서 화면·문구·동작을 모두 확인하고 확정한 내용이다. 실행 계획은 `.claude/plans/persona-report-redesign.md`.

## 1. 문제

현재 리포트 관련 화면은 `ResultsPage`(결과 + 좋아요한 건물 + 추천을 한 페이지에 나열)와 `BoardReportPage`가 같은 `PersonaReport` 컴포넌트를 공유하지만, 진입 상황별 경험이 정리돼 있지 않다.

1. 스와이프 종료 직후 리포트가 한 장의 긴 페이지로 쏟아져 "내 취향을 눈치챘다"는 순간이 약하다.
2. 로딩이 스피너 하나라 "이미 만든 걸 불러오는 중"인지 "새로 만드는 중"인지 구분되지 않는다.
3. 실패·빈 상태(결과 로드 실패, 좋아요 0건, 생성 실패, 보드 없음)가 화면마다 제각각이다.
4. 이미지에는 수동 재생성이 없고(자동 생성 1회), 실패해도 사용자가 다시 시도할 방법이 없다.
5. 소유자 / 타인 / 공유 링크 진입별 차이가 문서로 정리돼 있지 않다.

## 2. 확정 설계

### 2.1 진입 흐름 5개

| # | 진입 | 흐름 |
|---|---|---|
| ① | 스와이프 종료 (Taste 탭) | 하단 `Finish & View Report` → 「리포트를 만드는 중이에요」 스켈레톤 카드 → **결과 카드 3장(가로 스와이프)** → 저장 시트 → 리포트 페이지(저장 완료 토스트) |
| ② | 앱 재진입 | 카드형 배너(썸네일 · 「이전에 완성된 리포트가 있어요」 · 페르소나명) → 「저장하고 프로필로」→ 저장 시트 → 리포트 페이지 / 「삭제」→ 토스트 |
| ③ | 내 프로필 → 보드 → 리포트 | 보드 상세(소유자) → 「페르소나 리포트 보기」 → 「리포트를 불러오는 중이에요」 → 리포트 페이지(소유자) |
| ④ | 발견 → 타인 프로필 → 보드 → 리포트 | 보드 상세(타인) → 리포트 페이지(타인) |
| ⑤ | 공유 링크 직접 진입 (`/board/:id/report`) | 불러오는 중 → 리포트 / (소유자 + 리포트 없음) 만드는 중 → 리포트 |

### 2.2 결과 카드 (①, 분석 결과만 — 좋아요한 건물·추천은 저장 후 페이지에서)

카드 크기는 Swipe 카드 영역과 동일(좌우 20px, 높이 560px). 가로 스와이프(터치·마우스 드래그·하단 점).

1. **페르소나** — 「페르소나 리포트」 라벨, 이름(24px), 한 줄 설명, 상세 설명, 페르소나 이미지
2. **패턴 분석 + 취향 분석** — 「왜 이런 결과가 나왔나요」, 패턴 문단, 태그, 취향 스펙트럼
3. **마무리** — 이미지 썸네일, 「분석이 끝났어요」, 페르소나명, 안내 문구, 「저장하고 프로필로」

### 2.3 리포트 페이지 (단일 컴포넌트)

**저장 후 도착 화면과 `/board/:id/report`를 같은 컴포넌트로 합친다.** (기존 `PersonaReport` + `BoardReportPage` 통합. 라우트는 `/board/:id/report` 유지.)

구성(위 → 아래): 메타 줄 → 페르소나(라벨 · 이름 · 한 줄 · 이미지 · 설명) → 패턴 분석 결과(+태그) → 취향 분석(스펙트럼, 이전 방식 안내) → 좋아요한 건물(작은 카드 가로 스크롤) → 추천 순위(1위 큰 카드 + 나머지 작은 카드 가로 스크롤) → 하단.

- **타인에게도 추천 순위를 동일하게 보여준다** (2026-10-22 결정).
- 하단: 소유자는 「리포트 재생성」 텍스트 링크, 타인은 「더 볼 게 없어요」.
- 소유자에게만 이미지 우상단 새로고침 버튼이 있다.

### 2.4 로딩 문구 — 상황별로 구분

| 상황 | 문구 |
|---|---|
| 스와이프 종료 직후(새로 분석) / 소유자가 리포트 없는 보드를 열어 자동 생성 | 「리포트를 만드는 중이에요」 |
| 저장된 보드의 리포트 열기 / 공유 링크로 열기 | 「리포트를 불러오는 중이에요」 |
| 이미지 | 「이미지 생성 중」 (말줄임표 없음) |

이유: 이미 만든 리포트를 열 때 "만드는 중"이라 하면 내용이 바뀌는 것처럼 오해된다. 구분 조건은 보드 조회 결과에 리포트가 있는지 여부.

### 2.5 실패 · 빈 상태 (빨강 경고 없이 중립 톤)

공통 빈 상태 컴포넌트(아이콘 · 제목 · 본문 · 버튼). 결과 단계 실패는 카드와 같은 크기의 상태 카드.

| 상태 | 제목 / 행동 |
|---|---|
| 결과 로드 실패 | 「리포트를 불러오지 못했어요」 · 다시 시도 |
| 좋아요 0건 | 「나의 건축 페르소나」 · **탐색 시작하기** |
| 리포트 페이지 생성 실패 | 「페르소나 리포트를 만들지 못했어요」 · 다시 시도 / 뒤로가기 |
| 리포트 없음 | 「아직 페르소나 리포트가 없어요」 |
| 보드 없음 · 비공개로 변경 | 자물쇠 아이콘 · 「볼 수 없는 보드예요」 · 프로필로 가기 / 뒤로가기 |

### 2.6 재생성 — 이미지와 리포트는 별개 기능

| | 이미지 재생성 | 리포트 재생성 |
|---|---|---|
| 위치 | 이미지 우상단 작은 새로고침 버튼 (**소유자 시점이면 모든 화면에서**: 결과 카드 · 저장 후 페이지 · 리포트 페이지) | 리포트 페이지 맨 아래 밑줄 텍스트 링크 (소유자만) |
| 확인 | 「이미지를 재생성하시겠습니까?」 | 「리포트를 재생성하시겠습니까?」 |
| 진행 중 | 이미지 자리가 「이미지 생성 중」 스켈레톤. 새로고침을 다시 누르면 토스트 「재생성 중입니다.」 | 링크 문구가 「재생성 중」 |
| 실패 | 새로고침 옆에 작은 글씨 「재생성에 실패하였습니다.」, **기존 이미지 유지** | 링크 아래 작은 글씨 「재생성에 실패하였습니다.」 |
| 성공 | 이미지 교체 | 문구 교체 + 토스트 「리포트를 재생성했어요」 |
| API | `POST /projects/:id/report/generate-image/` `{regenerate:true}` | `POST /projects/:id/report/generate/` `{regenerate:true}` |

- 서버 동작(확인됨, `views/reports.py`): 리포트 재생성은 `final_report` · `axis_scores`만 저장하고 이미지는 건드리지 않는다. 이미지 재생성은 성공 시에만 저장하므로 실패해도 기존 이미지가 남는다. 이미지는 재생성 시점에 저장된 리포트를 바탕으로 그려진다.
- **취향 분석 그래프는 보통 바뀌지 않는다** — 좋아요한 건물에서 결정론적으로 계산되므로. 바뀌는 경우는 (a) 이전 방식으로 저장된 `axis_scores`가 새 방식으로 바뀔 때, (b) 보드의 좋아요한 건물이 달라졌을 때뿐이다.
- 이전 방식 분석 안내(「…리포트를 재생성하면 최신 분석을 볼 수 있어요」)는 문구를 그대로 두고, 「재생성하기 ↓」 링크로 하단 재생성 링크와 연결한다 (누르면 스크롤 + 강조).

### 2.7 이미지 상태

- 실패: 중립 면 + 「이미지를 만들지 못했어요」 + 소유자에게만 파란 테두리 「다시 시도」 (빨강 제거).
- 없음(타인 / 생성 전): 픽토그램 대신 액센트 그라데이션 면에 페르소나 이름이 은은히 비치고 「아직 페르소나 이미지가 없어요」.

### 2.8 보드 상세

커버 카드(페르소나 이미지 + 스크림 + 이름 24px + 메타) → 한 줄 설명 → 주 행동 「페르소나 리포트 보기」(pill 44px, 아이콘 없이 글자만). 소유자: 편집 · 공유 원형 버튼. 타인: 「♥ 좋아요」 pill. 리포트가 없는 보드에는 리포트 버튼 없음.

## 3. 결정 기록 (2026-10-22, 사용자)

1. 리포트 페이지는 **새 라우트를 만들지 않고 `/board/:id/report`를 공용 컴포넌트로** 교체하고, 저장 후 이동도 같은 컴포넌트를 쓴다. (컴포넌트 통합)
2. 타인에게도 추천 순위를 동일하게 보여준다.
3. 디자인 기준 밖의 값(본문 13px, 태그 11px, 좌우 여백 28px 등)은 **일단 그대로 유지하고 예외로 기록**한다. 승인은 나중에. → `DESIGN.md` §11.
4. 새 모션 규칙을 `DESIGN.md`에 넣는다. → `DESIGN.md` §3.5a.
5. 이전 방식 안내 문구는 「최신 분석」 그대로.
6. 리포트 재생성 이후 이미지에 대한 안내 문구는 넣지 않는다 (이미지는 그대로 유지됨이 확인 팝업 문구에 포함).

## 4. 열린 항목 (구현 중 확인)

- 보드 조회 API가 좋아요한 건물 · 추천 순위를 함께 주는지 (리포트 페이지가 둘 다 보여줌). 없으면 응답 확장 필요.
- 로딩 문구 구분에 쓸 필드(리포트 존재 여부).
- 하단 고정 버튼(Finish · 저장) 폭 = 실제 `TabBar` 폭. 시연은 200px 가정값이라 실제 값을 읽어 맞출 것.
- 이미지 재생성 중복 요청: 서버가 최대 25초 대기 후 202 `in_progress`를 돌려준다. 「재생성 중입니다」 토스트는 202 응답 또는 `reportImageJobs` 스토어 상태와 연결.
- 시연의 placeholder(건축가 · 연도, @handle, 건물 12개, ♥ 4)는 실제 필드로 대체.
- 재진입 배너 「삭제」의 확인 단계 여부(시연은 즉시 삭제 + 토스트).
- 프로필 보드 카드 커버 · People 카드 · 공유 문구는 **변경 없음**.
