# 취향(Taste) 시작 화면 개편 — 확정 설계

**작성** 2026-10-11 · **상태** 결정 확정, 구현 진행 중 (1·2단계 완료) · **브랜치** `feature/algo-taste-start`
**취향 시작 개편에 한해 이 문서가 기준입니다.** 대화·메모·설계 초안과 다르면 이 문서를 따르고, 결정이 바뀌면 이 문서를 먼저 고칩니다. 알고리즘 전체의 기준 문서는 `docs/algorithm.md`이며(현재 운영 코드 설명), 개편이 끝나면 이 문서의 알고리즘 결정(§3–§6, §8)을 algorithm.md 담당자가 정리해 그쪽으로 합칩니다.

## 0. 용어

| 용어 | 뜻 |
|---|---|
| **태그** | 사용자 문장에서 인식한 조건 하나. 예: 용도=주거, 나라=일본, 재료=목재 |
| **원함 / 제외** | 태그의 방향. "벽돌로" = 원함, "벽돌은 아니고" = 제외 |
| **해제** | 이전 회차 태그를 없애는 것. "일본일 필요는 없어" |
| **회차** | 입력 한 번 → 태그 + 카드 세 장. 다시 입력하면 새 회차 |
| **후보 묶음 (풀)** | 스와이프 세션 동안 카드를 고르는 건물 집합 |
| **맞춤 카드 / 확인 카드** | 4번째 카드부터 섞어 내는 두 종류 (§5-3) |

## 1. 전체 흐름

```
입력 → [보내기] → 태그 인식(JEV) → 일치도 1~3위 세 장
   ├─ [다시 찾기] → 같은 태그로 다음 세 장
   ├─ 다시 입력 → 새 회차 (태그 이어짐)
   └─ [이 세 장으로 스와이프 시작] → 세 장 = 덱 1~3번 → 4번째부터 반응 기반 추천
```

- 기존 Gemini 대화(되묻기)는 **없앱니다.**
- 새로 시작(`/search`)과 기존 보드 이어가기(`/search/보드번호`) **둘 다** 이 흐름을 씁니다.

## 2. 화면 (확정)

**첫 화면 (위에서 아래)**
1. 로고: 기존 **Arch|ibe 글자 로고** (20px/700, 두 색)
2. 헤드라인: "Let's discover your / **architectural taste.**" (30px/500, 둘째 줄 파랑, 한·영 공통)
3. 입력창: 3줄, 모서리 18px, 글자 13px
   - 안내 문구: **"예: 정원이 있는 일본의 목조 주택"** / "e.g. Japanese timber houses with a garden". 이 예시는 네 조건을 모두 만족하는 건물이 DB에 31곳 있음
   - 보내기 버튼: 34px 정사각형, 모서리 10px, 흰 화살표
- 예시 칩은 **없앰**
- 실시간 태그 표시(입력 중 패널)도 **없앰**. 태그는 보낸 뒤에만 나옴

**회차 화면**
- 내 문장 말풍선 → 태그 줄(앞 카드 기준 ✓ 일치 / ✕ 불일치 흐리게) → 카드 세 장 겹침 → "태그 N개 중 M개 일치" + "k / 3" → 버튼 두 개
- 카드 넘기기
  - 오른쪽 → 왼쪽으로 밀기, **→ 키** = 다음(1→3위)
  - 왼쪽 → 오른쪽으로 밀기, **← 키** = 이전(3→1위)
  - 탭 = 다음
  - **1위·3위에서 막힘**(순환 없음). 입력창에 글자를 치는 중에는 방향키가 카드를 넘기지 않음
- 버튼: "이 세 장으로 스와이프 시작"(주 버튼) / "다시 찾기"(보조)
- 다시 입력하면 새 회차가 아래에 쌓이고, 이전 회차는 위로 스크롤해서 다시 볼 수 있음
- **모든 회차**에서 스와이프 시작 가능 (그 회차의 세 장으로)
- 하단 입력창: 모서리 18px, 같은 정사각형 보내기 버튼

**버튼 색**: 라이트 #3D444D / 다크 **#545D68**, 글자·화살표 흰색

**글자 크기**: 앱 공통 단계표(24/20/16/14/12px)를 따름. 단계표에 없는 13px은 입력창 글자에만 씀(시안 결정)

## 3. 태그 인식 (JEV)

**도구**: TypeSafe JEV (선택지형 판정 모델). `requests`로 직접 호출(공식 SDK 안 씀), 시간 초과 2초, 실패하면 **단어 사전 대조**로 대체. **보내기 1번에 호출 1번.**

**태그 항목 (8개)**

| 항목 | 내용 | 비고 |
|---|---|---|
| 용도 | 넓은 용도(program 13종, 'Other' 제외) **또는** 구체적 건물 유형(typology 35종) | 하나의 태그로 합침. 일반어(주거·주택·건물)는 넓은 용도, 구체어(단독주택·아파트·도서관)는 건물 유형 |
| 스타일 | 12종 | Industrial(스타일·분위기)은 하나로 합침 |
| 분위기 | 12종 | **Warm(분위기·색감)은 하나로 합침** |
| 색감 | 8종 | |
| 재료 | 12그룹 (목재·금속·콘크리트·돌·벽돌·미장·타일·흙·유리·직물·플라스틱·기타) | 그룹마다 원함 / 제외 / 언급없음 |
| 나라 | 정리된 나라 이름 153개 | |
| 연도 | 숫자("2010년대", "2000년 이후")는 규칙으로 읽음. 시대 말("최근", "근대", "옛날")은 JEV | 숫자가 있으면 시대 말은 무시 |
| 지어짐 여부 | 지어진 것만 / 미준공 포함(기본) / 미준공만 | 미준공 = 연도가 올해보다 뒤인 건물 |
| 건축 요소 | 13종(중정·정원·아트리움…) | 요소 태그 **또는** 설명문 언급으로 판단 |

**규칙**
- JEV 질문에 "**새 메시지에 명시적으로 말한 것만**, 추측 금지, 쓴 언어 ≠ 나라" 규칙을 넣음. 이 문구 없이는 정확도가 무너짐(스파이크 결과)
- **확률 기준값 없음**: JEV가 '없음' 외의 답을 고르면 채택. 확률은 기록만 함
- 회차가 넘어가도 태그는 **이어짐**. 이전 태그마다 유지 / 해제 / 제외를 JEV가 판정
- 같은 항목에 새 값을 말하면 교체("스페인으로" → 일본 대신 스페인). 재료·요소는 여러 개 가능
- 태그를 탭해서 지우는 기능은 **없음**(채팅으로만)
- 생성하는 문구는 그때 언어 하나로만(두 언어 동시 생성 안 함)

**검증 결과**(스파이크, 60문장 × 2~3회): 이전 태그 처리 100%, 재료 99%, 다른 항목 96~100%, 응답 약 0.3초, 요청당 약 0.3원

## 4. 첫 세 장 고르기

- 점수 = 맞은 **원함** 태그들의 가중치 합 − 맞은 **제외** 태그들의 가중치 합(감점)
- **가중치**: 용도 3 · 나라 3 · 재료 2 · 스타일 2 · 연도 2 · 지어짐 2 · 요소 2 · 분위기 1 · 색감 1
- **제외는 감점이지 빼기가 아님.** 벽돌 건물도 나올 수 있지만 순위가 내려감
- 점수 순 1~3위. 동점이면 출처 수 → 신뢰 등급 → ID 순 (**항상 같은 결과**)
- 화면의 "N개 중 M개 일치"는 **가중치 없이 개수**로 셈(N = 원함 태그 수)
- 맞는 건물이 3곳 미만이면 덜 맞는 건물로 채우고, 빠진 태그는 ✕로 흐리게 표시
- 원함 태그가 하나도 없으면("그냥 멋진 거") 다양한 건물 세 장
- **다시 찾기**: 같은 태그, 그 회차에서 이미 본 카드는 빼고 다음 세 장. 넘긴 카드는 싫어요로 치지 않음
- 매칭은 **정확히 일치 / 단어 단위 일치**("포함" 검색 안 씀 — textile이 tile에 걸리는 문제 방지)

## 5. 스와이프 알고리즘

### 5-1. 후보 묶음
- **태그 중 하나라도 맞는 건물**을 점수 순으로. 처음 150곳, 20곳 아래로 줄면 다음 순위 150곳 추가
  - 태그가 전부 맞을 필요 없음. 점수가 낮은 건물은 뒤로 밀릴 뿐
  - 분위기·색감(가중치 1)만 못 맞춘 건물이 용도·나라(가중치 3)를 못 맞춘 건물보다 자연히 앞에 옴
- **태그가 하나라도 맞는 건물을 전부 소진하면**: 태그 조건 없이 DB 전체에서 좋아요와 닮은 건물로 이어 감. 화면에 알리지 않음(Q9 결정, 2026-10-11)
- 원함 태그가 없으면: 다양한 건물로 묶음을 만들고 제외 감점만 적용
- 이어가기: 그 보드에서 이미 좋아요·싫어요한 건물은 묶음에서 뺌

### 5-2. 처음 세 장
- 고른 회차의 세 장이 **무조건 덱 1~3번**(순서 그대로)
- 기존 "서로 다른 10장 고정 + 좋아요 4개부터 맞춤 추천"을 **대체**

### 5-3. 4번째 카드부터 (하나의 규칙)
매 장마다 **맞춤 카드** 또는 **확인 카드**를 냄.

- **맞춤 카드**: 점수가 가장 높은 건물
  `점수 = 태그 비중 × 태그 점수 + (1 − 태그 비중) × 좋아요와의 닮음 − 0.3 × 넘긴 카드와의 닮음 − 0.3 × 이미 본 카드와의 겹침`
  - 태그 비중: 좋아요 0개일 때 1.0 → 좋아요 6개쯤 0.3. **0까지는 안 내려감**(태그는 끝까지 유지)
  - 최근 좋아요일수록 더 중요하게, 좋아요 11개부터는 취향 두 갈래로 봄(기존 방식 유지)
  - **넘긴 카드를 반영함**(기존 코드에서 빠져 있던 부분)
- **확인 카드**: 후보 묶음 안에서, 태그 점수가 남은 최고점의 절반 이상인 건물 중 **지금까지 본 모든 카드와 가장 다르게 생긴** 건물

**비율** (지금까지의 반응으로 자동 조절)

| 상황 | 맞춤 : 확인 |
|---|---|
| 좋아요 0개 (고른 세 장을 다 넘김 포함) | 0 : 1 (전부 확인) |
| 좋아요 1개 | 1 : 1 |
| 좋아요 2개 이상, 서로 비슷함 | 3 : 1 |
| 좋아요 2개 이상, 서로 다름 | 1 : 1 |
| 최근 3장 연속 넘김 | 최소 1 : 1 |
| 최근 5장 연속 넘김 | 0 : 1 |

- "서로 비슷함" = 최근 좋아요 4개끼리의 평균 닮음이 0.6 이상(실제 데이터로 한 번 보정)
- "생김새" = DB에 미리 계산된 건물 좌표(384차원). 사진이 아니라 **외관 설명글**을 숫자로 바꾼 것

### 5-4. "취향 찾았어요"
- 기존 판정(좋아요 중심의 움직임이 충분히 작음)에 **최소 8장** 조건 추가

### 5-5. 적용 범위
- 3단계에서는 **새 흐름으로 시작한 세션에만** 적용("새 방식" 표시)
- 진행 중인 옛 세션, 디스커버리에서 넘어온 세션은 5단계에서 새 규칙으로 옮김

## 6. 저장과 이어가기

- **DB 구조 변경 없음.** 세션: 원래 조건 칸에 `selector: taste_v2` + `taste_tags`. 보드: 조건 칸에 `taste_tags`
- 저장된 태그도, 브라우저가 보낸 태그도 **서버가 (항목, 값, 방향)만 읽어 다시 만듦**(위조 방지)
- 이어가기는 보드의 태그를 시작점으로 깔고 시작
- 옛 방식 보드는 옛 조건을 태그로 최대한 바꿈(도시·이미지 초점처럼 대응이 없는 것은 버림)

## 7. 그 밖의 확정 사항

- **DB 데이터 보정**: Make DB 정리 전까지 우리 코드에 **임시 매핑표**(`taste_start/normalization.py`: 나라 표기 묶기, 재료 154개 값 → 12그룹). 정리되면 표를 지우고 DB 칸으로 교체. 요청서는 `docs/db-data-quality-handoff.md`(따로 전달)
- **옛 Gemini 대화 코드**: 새 흐름을 테스트한 뒤, **PR 올리기 전에 같은 브랜치에서 삭제**(되돌리기 = git 되돌리기 + 재배포)
- **기존 코드 문제**(폰에서 로고 가림, 리포트 그래프 영어 라벨 잘림, 소셜 제목 겹침, 영어 사용자에게 한국어로 나오는 칩·문구): 이번 범위 밖. 별도로 결정
