# 취향 분석 결과 → 저장 → 프로필 흐름 설계

**작성** 2026-09-17 · **브랜치** `feature/sns-results-save-cta` · **상태** 확정

## 1. 문제

Discovery → Taste로 넘어가 리포트를 생성하면:

1. `SaveBoardModal`이 **자동으로 떠서 리포트를 가린다** (`App.jsx:458`, `:675`)
2. 저장을 마쳐도 **결과 화면에 그대로 머문다** (`handleBoardSaved`는 토스트만 띄움)
3. 나가려면 **뒤로가기**를 눌러야 한다

이미 저장이 끝났는데도 **"저장이 안 된 것 같은"** 느낌이 드는 이유. 기능 결함이 아니라 완결감(closure)의 부재다.

## 2. 검토한 대안

| 안 | 내용 | 판단 |
|---|---|---|
| A | 모달을 강제(`나중에` 제거)하고 저장해야 리포트 열람 | 리포트를 보기도 전에 이름부터 정해야 함 — 순서가 부자연스러움 |
| **B** | **모달 자동 노출을 없애고 상단 CTA 버튼으로 유저가 마무리** | **채택.** 리포트를 먼저 보고 저장하는 자연스러운 순서 |
| C | 버튼 클릭 시 기본값으로 즉시 저장 | 이름·공개여부 선택권이 사라짐. 공개여부는 발견 피드 노출과 직결되어 유저가 정해야 함 |

## 3. 확정 설계

### 흐름

```
리포트 생성 완료
   → 리포트 화면 (모달 없음, 상단에 [저장하고 프로필로])
   → 버튼 클릭 → SaveBoardModal (이름 + 공개여부)
   → 저장 → 프로필(/user/me)
```

### 변경 3가지

**① 자동 모달 제거** — `App.jsx` 두 곳의 `setShowSaveModal(true)` 제거. 리포트가 완성되면 가림막 없이 리포트부터 보여준다.

**② 결과 화면 상단 CTA** — `ResultsPage` 헤더 영역에 `저장하고 프로필로` 버튼. 리포트를 다 본 뒤 유저가 스스로 마무리를 누르는 순서.

**③ 저장 후 프로필 이동** — `handleBoardSaved`에 `navigate('/user/me')` 추가. 흐름이 프로필에서 끝난다.

**부수: 모달의 `나중에` 제거** — 버튼을 눌러 연 모달이므로 출구를 저장으로 일원화. 단 **backdrop 클릭은 유지** — 실수로 눌렀을 때 빠져나갈 길이 없으면 갇힌 느낌이 되고, 이 경우 리포트 화면으로 돌아올 뿐 잃는 것이 없다.

### 재사용

새로 만드는 것은 **버튼 하나**뿐. `SaveBoardModal` · 저장 API · `handleBoardSaved`는 기존 것을 그대로 사용. 버튼 스타일은 `PersonaReport`의 기존 CTA 값(`--accent-1`, `radius 999`, `minHeight 44`)을 따른다.

### 엣지 케이스

- **이미 저장된 보드** (임시가 아닌 상태로 결과 화면 재진입) → 모달이 불필요하므로 버튼이 바로 프로필로 이동
- **저장 실패** → 기존 모달의 에러 표시가 그대로 동작, 모달은 열린 채 재시도 가능
- **`tempCompletedProject` 재진입 배너** → 자동 모달이 사라지면 임시 보드 발생 여지도 줄지만, 이미 만들어진 임시 보드를 위해 그대로 둔다(제거는 별건)

## 4. 테스트

단위 테스트 미추가 — 네비게이션과 조건부 렌더라 기존 `node --test`(순수 모듈 대상) 범위 밖.

수동 절차: discovery → taste → 리포트 생성 → 모달이 뜨지 않는지 → 상단 버튼 → 모달 → 저장 → 프로필 도착 → 프로필 보드 목록에 존재하는지.
